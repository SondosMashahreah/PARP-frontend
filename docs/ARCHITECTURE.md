# دليل الفرونت

تنظيم قائم على الصفحات والميزات، يحافظ على التصميم وروابط الصفحات. كل شاشة لها JSX وCSS داخل مجلدها.

| التعديل | المكان |
| --- | --- |
| صفحة محددة | `src/pages/<Name>/<Name>Page.jsx` و`<Name>Page.css` |
| نصوص صفحة بالعربي والإنجليزي | `<Name>Page.content.js` بجانب الصفحة |
| تفاعل المستودع والمؤتمر والدليل والقالب والأخبار والدعم | `pages/<Name>/components/`؛ النسخة الإنجليزية تنتهي بـ `.en.jsx` |
| الخريطة المدرسية | `pages/Map/MapPage.jsx` |
| خريطة المرصد البحثية | `pages/ObservatoryMap/ObservatoryMapPage.jsx` |
| أفضل الممارسات | `pages/Practices/`؛ البيانات والفلترة في `features/practices/` |
| الهيدر والسايد بار | `components/Header/` |
| تصميم إطار الصفحات المشترك | `components/platform/PlatformPageFrame.jsx` و`PlatformPage.css` |
| تنسيق عناصر التفاعل المشتركة | `components/platform/PlatformExperience.css` |
| جلب البيانات وقواعد الميزات | `features/<feature>/application`, `data`, `domain` حيث توجد |
| تسجيل الدخول | `features/auth/`؛ شاشته في `pages/Login/` |
| سجل الصفحات | `routing/pageRoutes.jsx`؛ الصفحات الخاصة والحماية في `App.jsx` |
| الثيم والخطوط | `styles/` |

CSS الصفحة يستورد التنسيق المشترك بدل نسخه. ضعي قواعدها الخاصة بعد الاستيراد، مع selector خاص عند الحاجة حتى لا يتغير تصميم بقية الصفحات.

`pages/Platform/platformPages*.js` أصبح فهرس بيانات توافق للبحث وقيم المنصة، وليس ملفًا يجمع واجهات الصفحات. مصدر النصوص الحقيقي بجانب كل صفحة. `/account` يبقى اسمًا بديلًا لشاشة الدخول ويملك ملفه الخاص.

اتجاه الاعتماد: الصفحة تجمع المكونات وتستدعي الميزات؛ منطق المجال لا يستورد صفحات أو React. أبقي المكونات المستخدمة في صفحة واحدة بجانبها، وانقلي المكون إلى `components` فقط عندما يكون مشتركًا فعليًا. لا تنقلي النصوص أو CSS العام إلى قواعد المجال.

## التحقق

`npm run build`
`npm run lint`
`npm test`

تم الاحتفاظ بكل محتوى الصفحات بالعربي والإنجليزي وبـ guest/member navigation وبصلاحيات المسارات. لم يتغير سلوك الأزرار التجريبية الموجودة مسبقًا، ولم تتحول إلى وظائف backend جديدة.
